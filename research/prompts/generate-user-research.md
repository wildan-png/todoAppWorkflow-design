Read `/brief/founder-brief.md` first.

Goal:
Produce a designer-team alignment document so all teams share the same assumptions about:
1) who the real primary user is
2) how they use the product day-to-day
3) which product flows and pain points matter most for V1.

Write output to:
`/research/user-research.md`

Style:
- Simple, concise language.
- Keep enough context for decision-making.
- No long narrative paragraphs.
- Prioritize design collaboration usefulness over broad market analysis.

Research focus:
- Primary user profile (and who is NOT primary for V1)
- Flow-relevant pain points (ranked)
- Unmet needs tied to product usage
- Current workarounds (interface/workflow level)
- Emotional drivers
- Shared team assumptions (working, testable)
- How users are expected to use the product (core flows + daily usage moments)
- Product design priorities (IA baseline, interaction direction, success signals)
- Open questions to validate
- Source notes

Required section order (exact):
## Target User Profile
## Key Pain Points
## Unmet Needs
## Current Workarounds
## Emotional Drivers
## Shared Team Assumptions (Working)
## How Users Are Expected to Use aTodo
## Product Design Priorities
## Open Questions to Validate
## Source Notes

Constraints:
- No duplicate headings.
- Keep `Key Pain Points` to top 4.
- Keep `Current Workarounds` to top 3.
- Keep each section concise (4-6 bullets max; fewer is fine).
- Do NOT add a separate `Market Signals` section in the main body.
- If market context is needed, include only 1 short directional bullet inside relevant sections.

Source quality:
- Prioritize: official reports, official docs/pricing, App Store reviews.
- Use Reddit/community content as directional only.
- Mark uncertain claims as “directional”.
- Include citations inline where possible.
